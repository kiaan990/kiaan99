# connect-dots

## Trigger phrases

- "have I solved this before?"
- "am I repeating myself?"
- "find related work"
- "connect the dots"
- "what's similar to ___"
- "is there prior art for ___"

## Purpose

Goes beyond keyword grep. Builds clusters of related notes by combining:

1. Shared tags
2. Shared `[[wikilink]]` neighborhoods
3. Textual similarity (token overlap or, when MCP is available, embedding-based)

Reports the cluster, not just hits. If a dense cluster has no pattern,
proposes one.

## Workflow

### 1. Extract the seed

Take the user's question. Extract:
- Noun phrases (problem domain)
- Stack mentions
- Verbs of intent ("dedupe", "rate-limit", "auth", etc.)

### 2. Build a candidate set

Run `vault-search/` on the seed. Take the top 20 hits (not 5 — wider net
this time). Filter to `60-retros/` + `70-patterns/` first; expand to
projects only if the retro/pattern set is thin.

### 3. Score pairwise similarity

For each pair (A, B) in the candidate set:

- `tag_overlap = |tags(A) ∩ tags(B)|`
- `link_overlap = |outlinks(A) ∩ outlinks(B)|`  (shared wikilink neighbors)
- `body_overlap = |tokens(A) ∩ tokens(B)| / |tokens(A) ∪ tokens(B)|`
  (Jaccard on lowercased, deduped, stop-word-filtered tokens)
- `score(A,B) = 3 * tag_overlap + 2 * link_overlap + 5 * body_overlap`

### 4. Cluster

Greedy cluster: sort pairs by score desc, merge into clusters whenever
both endpoints are above threshold (`score ≥ 4`). Stop when no more
merges possible.

### 5. Report each cluster

For each cluster of ≥2 notes:

```
Cluster: <auto-generated name from shared tags>
  - [[<slug>]] (retro, 2026-03-12) — <one-line>
  - [[<slug>]] (pattern) — <problem one-line>
  - [[<slug>]] (project, archived) — <goal one-line>
  Shared tags: tag1, tag2
  Existing pattern in cluster: [[pattern-...]] | NONE
```

### 6. Pattern proposals

For any cluster of size ≥3 with **no** pattern file:

> 💡 No pattern exists for this cluster. Propose creating
> `pattern-<short-name>.md` capturing the common solution.
> Suggested origin: <oldest retro in cluster>.

Ask the user if they want to scaffold it now (cp from
`90-meta/templates/pattern.md`, pre-fill `problem_domain` from shared tags).

### 7. Single-hit case

If only one note matches and no cluster forms, fall back to a
`vault-search/`-style report with the single hit.

### 8. Empty case

If zero hits, say so explicitly. Suggest the user is in fresh territory
and the result of this work will likely produce a high-value pattern —
prime them to capture it.

## When MCP is available

Replace the Jaccard token similarity in step 3 with the MCP server's
search-by-similarity tool if exposed (some Obsidian MCP servers wrap
embedding-based search). Tag/link overlap stays the same.
